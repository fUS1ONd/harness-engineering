# Агентский контур UI/UX и функциональной верификации приложений

Нужен воспроизводимый способ проверять UI/UX и функциональность приложений (начиная с `rumap-android`) руками ИИ-агента до того, как владелец получит debug-сборку или выйдет prod-релиз. На основном VPS нет `/dev/kvm`, поэтому мы выбрали гибридную архитектуру: быстрые headless-проверки на JVM выполняются на VPS, а живой headless KVM Android Emulator крутится на `ssh home` (`home-server`) строго на HDD `/mnt/data/android/` (SSD `/dev/sda2` не используется), доступном с VPS по SSH/ADB.

Управление для агента разделено на два слоя: тонкий CLI в `harness-engineering` отвечает за жизненный цикл стенда, снапшоты, проброс `adb`, сбор `logcat`/крашей и вызов white-box ручек (с расчётом на последующее расширение на веб/боты), а готовый UI-драйвер (`@mobilenext/mobile-mcp` или `Maestro`) — за accessibility-дерево, тапы, ввод, свайпы и скриншоты.

## Considered Options

- **T3 Device Hub на локальной машине / личном телефоне как основной стенд** — отвергнуто как основной вариант из-за зависимости от включённого локального хоста и риска для личных данных на телефоне (оставлено как опциональный стенд для проверок реального радио/SIM).
- **Облачная ферма устройств (Firebase Test Lab / Genymotion)** — отвергнуто из-за стоимости и отсутствия интерактивного исследовательского цикла агента.
- **Только безэмуляторные JVM-тесты на VPS** — недостаточно для живого исследовательского UX-прогона («потыкай как юзер»).

## Consequences

- Эмулятор доступен 24/7 с VPS по SSH/ADB без участия локальной машины владельца.
- Все артефакты Android SDK, системные образы, AVD и снапшоты обязаны храниться в `/mnt/data/android/` на `ssh home` (запрещено писать на системный SSD).
- Агент формирует структурированный отчёт с рубрикой оценки; заведение GitHub Issues выполняется только после явного подтверждения владельца.
