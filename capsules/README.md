# Капсулы (`SkillCache` executor-driven)

Механизм компиляции повторяющихся агентских рутин в параметризованные капсулы (по мотивам *SkillCache*, arXiv:2611.10022).

## Зачем это нужно

Вместо того чтобы модель на каждом повторе тратила 5–10 ходов на механическую оркестрацию (перечитывая весь контекст на каждом шаге), раннер [`scripts/skillcache-run`](../scripts/skillcache-run) прогоняет смежные детерминированные программы подряд, сам прокидывает их JSON-выходы через биндинги и возвращает управление модели **только** когда:
- не хватает входных биндингов (`needs_bindings`);
- встретился шаг, требующий суждения модели (`your_steps`);
- упала программа (`your_steps` с `program_failed: true` — **деоптимизация** только этого шага; остальной план остаётся скомпилированным и продолжает работу после `continue`);
- все программные шаги завершены (`complete`).

## Правило создания новой капсулы (one-trace + replay)

1. **Не компилировать zero-shot.** Сначала выполнить задачу обычным скиллом и убедиться, что результат принят (зелёные тесты/ревью/подтверждение владельца).
2. Вынести детерминированные операции в `capsules/<name>/programs/`, параметризовав request- и workspace-зависимые значения через `bindings` в `capsule.json`. Шаги с суждением оставить как `type: "nl"`.
3. Прогнать квалификацию через 3 гейта до использования в бою:
   ```bash
   ./scripts/skillcache-run qualify capsules/<name>
   ./scripts/skillcache-run qualify capsules/<name> --replay --examples '{"...": "..."}'
   ```
4. Получить компактный промпт для брифа агента (без утечки исходников программ в контекст):
   ```bash
   ./scripts/skillcache-run prompt capsules/<name>
   ```

## Доступные капсулы

- [`land-ticket`](land-ticket/capsule.json) — слияние готового тикета из временного worktree в ветку усилия: проверка чистоты → `git rebase` → полные проверки → `git merge --ff-only` → удаление временного worktree и ветки `t3/*` → верификация постусловий.
