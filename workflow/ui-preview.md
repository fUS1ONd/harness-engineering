# Образец и визуальная сверка интерфейсов — до кода

Владелец оценивает функциональность глазами пользователя: экраны, тексты, кнопки, страницы, отчёты. Внутренняя реализация — зона оркестратора, тестов и ревью.

## Правило: сначала макет в чате, потом код

Для любой задачи, меняющей пользовательский интерфейс (веб-страницы, экраны Telegram-бота, уведомления, графики, отчёты):

1. **До начала кодирования** агент/оркестратор готовит макет (или обновлённый образец) на реалистичных данных, включая состояния ошибки, пустого вывода и ожидания.
2. **Обязательный показ в треде T3 Code:** макет рендерится прямо в чат через `html_preview` → `html_render` (самодостаточный HTML без фона у `html`/`body` и без лишних рамок, с использованием CSS-переменных темы T3). Недостаточно просто положить `.html`-файл на диск — владелец должен увидеть интерфейс в чате.
3. Только после одобрения образца (`Одобрено: <дата>`) тикет переходит в `ready-for-agent`.

## Верификация по образцу

1. Первый коммит реализации — тест (golden или сценарный), проверяющий соответствие вывода утверждённому образцу.
2. Исполнитель не меняет утверждённый образец самовольно. Если требование образца технически невыполнимо — останавливается и пишет причину в `## Answer`.
3. Для CLI-симуляторов ботов/интерфейсов проверка идёт по реальным названиям кнопок и сценарию целиком, а финальный отчёт владельцу содержит результат «было → стало» и лог прохождения сценария.
